================================================================================
  IMPLEMENTATION PLAN: WhatsApp Chatbot with Claude AI + Kommo CRM Integration
================================================================================

  CONTEXT
  -------
  The project is a WhatsApp appointment booking chatbot for a barber shop/salon,
  built with TypeScript + Express + Supabase. It currently uses a rule-based
  finite state machine (13 states) where users navigate via numbered menus.

  Goals:
    1. Add Claude AI (Anthropic) for intent-based routing -- users can type
      naturally (e.g., "quiero un corte el viernes a las 3") and the AI detects
      intent + extracts entities, then feeds them into the existing state machine.
    2. Integrate Kommo CRM as the primary source of truth for contacts/leads,
      replacing the Supabase "clients" table. Supabase remains for scheduling
      data (services, availability, appointments).
    3. Keep WhatsApp via Meta Cloud API (current setup, no changes).


================================================================================
  ARCHITECTURE
================================================================================

  WhatsApp Message
    -> Express Webhook (unchanged)
    -> normalizePhone() (unchanged)
    -> processMessage(phone, text)
        -> getSession(phone)
        -> [NEW] parseIntent(text, ctx)         -- Claude Haiku API
        ->        returns { intent, entities }
        ->        pre-populates ctx fields
        ->        skips states when possible
        -> routeToHandler(ctx, message)          -- existing state machine
        -> [MODIFIED] handlers use Kommo for contacts
        -> updateSession(phone, ctx)
    -> sendWhatsAppMessage() (unchanged)

Key principle: The AI is a thin parsing layer. The state machine remains the
core engine. If AI fails, fallback to menu-driven flow.

3.4 Create bridge tools (replace Supabase client lookups)

    src/tools/get-client-kommo.ts
    - Calls findContactByPhone() from Kommo
    - Also upserts a minimal record in Supabase "clients" table (for FK
      integrity on appointments)
    - Returns same GetClientOutput shape as existing get-client.ts

    src/tools/register-client-kommo.ts
    - Calls createContact() in Kommo
    - Also upserts in Supabase "clients" table (for FK)
    - Returns same RegisterClientOutput shape as existing register-client.ts

    WHY DUAL-WRITE?
    The appointments table has client_id FK referencing clients(id).
    New contacts live in Kommo, but we need a Supabase clients row for the FK.
    This is a transition strategy -- Kommo is source of truth for contact data,
    Supabase clients is a thin shadow table for FK integrity only.

================================================================================
  PHASE 4: WIRE AI + KOMMO INTO STATE MACHINE
================================================================================

4.1 Modify src/chatbot/handler.ts (main entry point)

    In processMessage(), after getSession() and before routeToHandler():

    1. Check if current state warrants AI parsing
       (GREETING, MAIN_MENU, or states expecting free text)
    2. Call parseIntent(message, ctx)
    3. If confidence > 0.5, attempt intent-based shortcuts:
       - BOOK_APPOINTMENT: resolve service by name (reuse searchServices()),
         resolve date (reuse parseUserDate()), pre-populate ctx fields,
         skip to the furthest possible state
       - VIEW_APPOINTMENTS: jump to VIEW_MY_APPOINTMENTS
       - CANCEL_APPOINTMENT: jump to CANCEL_APPOINTMENT
       - GREETING: reset to GREETING
       - GOODBYE: jump to DONE
    4. If shortcut fails or confidence low, fall through to routeToHandler()

    Shortcut logic for BOOK_APPOINTMENT:
    - All 3 entities (service + date + time) -> jump to CONFIRM_BOOKING
    - Service + date                         -> jump to CHECK_AVAILABILITY
    - Service only                           -> jump to CHECK_AVAILABILITY
    - No entities                            -> jump to BROWSE_SERVICES

  KOMMO API REFERENCE (QUICK CHEAT SHEET)
================================================================================

Base URL:  https://{subdomain}.kommo.com/api/v4
Auth:      Authorization: Bearer {access_token}
Rate limit: 7 requests/second

Key endpoints:
  GET  /contacts?query={phone}           Search contacts by phone
  POST /contacts                         Create contact (body is array)
  PATCH /contacts/{id}                   Update contact
  POST /leads                            Create lead (body is array)
  PATCH /leads/{id}                      Update lead / move pipeline stage
  GET  /leads/pipelines                  List pipelines
  GET  /leads/pipelines/{id}/statuses    List stages in pipeline

Contact phone field:
  {
    "field_code": "PHONE",
    "values": [{ "value": "+5491112345678", "enum_code": "MOB" }]
  }

Lead with linked contact:
  {
    "name": "Turno: Corte de pelo - 15/02/2026 15:00",
    "price": 5000,
    "pipeline_id": 12345,
    "status_id": 67890,
    "_embedded": {
      "contacts": [{ "id": 583338, "is_main": true }]
    }
  }

Close lead as won:  PATCH /leads/{id}  { "status_id": 142 }
Close lead as lost: PATCH /leads/{id}  { "status_id": 143 }
